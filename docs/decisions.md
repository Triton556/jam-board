# Decisions beyond the specification

BRIEF.md v2 remains the acceptance basis. Decisions 1–18 were accepted after M2; the M3 additions below follow the accepted M3 brief. Work stops after M3.

1. **Development symbols.** This machine's MSVC 14.44 rejects SQLite compilation with cc-rs `/Z7` (D8050). Repeating compilation with only `CARGO_PROFILE_DEV_DEBUG=0` changed succeeded. `[profile.dev] debug = 0` makes that local workaround reproducible without system changes; release settings are unaffected. Native source-level debugging requires revisiting this setting.
2. **Presence and configuration metadata.** Updating `last_seen_at` on an existing member and writing local `settings` do not add jam activity. A first agent registration adds exactly one `member.joined`; every business mutation adds one activity row. An archive reason is inserted as a comment inside the archive transaction, covered by its single `task.archived` event.
3. **Task ordering.** `afterKey` is the immediate predecessor and `beforeKey` the immediate successor in the destination column. One supplied neighbor selects its adjacent insertion slot. Both must be adjacent, active, in the same jam and destination status; the moved task cannot be its own neighbor. With no neighbors, append.
4. **Globally unique keys across jams.** The first jam uses `JB`; later jams use the first unused prefix `JB2`, `JB3`, etc. Each jam still has its own transactional sequence. This fills the unspecified prefix-selection behavior while satisfying globally unique task keys.
5. **List pagination.** Cursors are non-negative decimal offsets into the filtered active-jam list ordered by `(position, key)`. They are not stable snapshots when tasks move between calls. The default limit is 50; values outside 1–200 return `validation`.
6. **Nullable updates.** Omitted `estimate`/`dueAt` preserve the stored value; explicit JSON `null` clears it. An idempotency retry returns the original task before validating changed create arguments and adds no new event.
7. **Agent handles and palette exhaustion.** Handles are lowercased alphanumeric names with other characters replaced by hyphens and edge hyphens removed. Collision with a human is a validation error. After six unique palette colors are used, assignment cycles through the palette. Existing agents retain their configured name/color/client.
8. **Board time.** `timeLeft` is a nullable integer count of remaining seconds, clamped to zero. The M3 UI will format it. An absent active jam returns `not_found`; a read never silently seeds data.
9. **Demo history.** The fixture uses the normal services for its 60 mutations, then backdates its event timestamps over 17 hours. Demo asset locations intentionally retain the relative paths specified in the brief. General asset creation stores references and never reads or copies the files.
10. **M1–M2 shell.** Frontend dependencies for future screens are deferred to M3–M5. Only the `board-changed` event is generated with tauri-specta; commands, API/mock adapters, query state and screen implementation remain M3+. The icon was generated early because Windows tauri-build requires an `.ico` even for the M1 shell; its source follows the specified sticker/J/star design.
11. **Event integers.** tauri-specta exports SQLite integer event sequences as JavaScript numbers. The meaningful supported range is JavaScript's safe integer range (up to 9,007,199,254,740,991). No decimal-string protocol was introduced.
12. **Local testing.** All disposable databases and logs are beneath `.dev-data/tests`. Test loopback HTTP and WebView2 diagnostics are local-only. The diagnostics port 9223 is a process-scoped test setting, not part of the application's shipped configuration.
13. **Build preparation.** Run `npm run prepare:sidecar` before direct workspace Cargo checks on a fresh clone. It compiles the real CLI and copies the target-suffixed binary required by `bundle.externalBin`. The Tauri dev/build hooks perform this automatically; generated binaries are ignored by Git.
14. **Recursive JSON type metadata.** The pinned Specta exporter cannot expand its inline `serde_json::Value` representation recursively. `ActivityEvent.payload` keeps its real `serde_json::Value` field, with a named recursive `JsonPayload` metadata type for export. No serialized bytes or dependency versions change. A regression test exports the real event and round-trips nested JSON.
15. **All development application directories.** Tauri's documented `appDirectoriesOverride` is set before creating the window when `JAM_BOARD_DATA_DIR` is present (or to the workspace `.dev-data` in debug builds). This keeps WebView2 caches and plugin window state within the development directory as required. The initial default-directory window creation failed with OS error 5; no permissions, registry, or global directories were changed. Release builds without the environment override keep Tauri's platform directories.
16. **Timestamp offsets.** Accepted RFC 3339 input is normalized to UTC before storage. Timezone metadata remains available on the jam.
17. **Windows test executable manifest.** A native Tauri test binary initially exited before the harness with `0xc0000139`; its ComCtl32 import includes `TaskDialogIndirect`. The application manifest selects Common Controls v6 but Cargo's library unit-test executable did not inherit it. The event-contract test now lives in the conventional integration-test target with Windows-only `rustc-link-arg-tests` manifest directives, following [Microsoft](https://learn.microsoft.com/en-us/windows/win32/controls/cookbook-overview) and [Cargo](https://doc.rust-lang.org/cargo/reference/build-scripts.html#rustc-link-arg-tests). Applying embedding directives to every target produced a duplicate manifest in the application binary; scoping them to integration tests avoids that. All test harnesses remain enabled.
18. **Reloading demo data.** A demo load creates a new active jam and preserves earlier jams and the global member registry. Agents are reused by handle. If they already have join events, extra handoff comments on an already-commented demo task maintain the required 60 new events. Backdating is scoped to the new jam; a regression test checks that the first jam's 60 events remain unchanged.

19. **Desktop identity.** `current_member_id` is local configuration metadata under decision 2. Creating a jam (including demo loading) selects its human creator in the same transaction. `add_self(name)` fills the missing-identity flow: it uses the existing human owner's member-creation service and then selects the new human. No actor ID is accepted in task command inputs. Missing or agent-valued identity blocks desktop task mutations.
20. **Typed desktop read models.** BoardSummary, AppState and onboarding inputs live in jam-core. TaskSummary now includes `commentCount` for cards; both paginated MCP lists and the unpaginated board compute it from comments. The generated Specta wire types retain nullable option fields; the single real bridge supplies explicit nulls for omitted frontend arguments. ApiErrorCode is a generated string union.
21. **Binding export on Windows.** The explicit export example needs the same Common Controls v6 manifest as integration tests (decision 17). Manifest linker directives are scoped separately to examples. The freshness test compares the exported bytes with committed bindings, normalizing only line endings.
22. **Mock data and loading.** The Rust export example writes the shared demo JSON using an isolated database below `.dev-data/fixture-export/`. Mock demo loading rebases the deadline to 31 hours and agent presence to now; task content comes from that fixture. Mock state is intentionally in memory. The production API loads no mock module or demo fixture.
23. **Keyboard cross-column placement.** The dnd-kit coordinate getter delegates vertical sorting to `sortableKeyboardCoordinates`. Left/Right selects the adjacent column and its end slot; subsequent Up/Down adjusts that slot. Both pointer and keyboard drops use the same neighbor calculation (`afterKey` predecessor, `beforeKey` successor, decision 3).
24. **Startup and shared timers.** The native window starts hidden and is shown after Rust settings select the theme, local fonts load and two paint frames pass (or an error screen is ready). Window-state restores geometry but excludes its VISIBLE flag so it cannot show the window early. A single 100 ms application clock expires highlights, presence pulses and notifications; countdown/presence use whole seconds. Paper grain is rasterized once in memory to a PNG data URL from the specified SVG turbulence.
25. **Compatible dependencies and local browsers.** `@hookform/resolvers` 6 could not resolve its optional effect-v3/effect-v4 dependencies together, so version 5.9.2 is used with React 19, react-hook-form 7 and Zod 4. No pinned brief dependency changed. Playwright 1.64 uses the installed Chrome Chromium engine (`channel: chrome`); no browser or system software was downloaded, respecting the network boundary. `sharp` is an Apache-2.0 development dependency for the requested WebP conversion; its Windows image-processing binary also carries LGPL-3.0-or-later notices.
26. **Live capture.** The real WebView2 compositor stream is sampled around 0/200/400/600/800/1000 ms, retaining actual sample and source-frame times. A short VP9 WebM is encoded locally from the captured stream with the installed browser's MediaRecorder; no external encoder, service or upload is used. Full native window screenshots are separate from content captures. The diagnostics port remains process-scoped under decision 12.

27. **M4 board fit and avatar labels.** Column gaps are 16 px, with the specified flexible 232–300 px columns. Tooltips mount in a viewport portal only while visible: hidden tooltip text must not enlarge the board's scrollable area. Avatar collision detection uses all loaded members, including offline members, so initials stay stable as presence changes.
28. **Table query details.** Selected tags match any selected tag; different filter categories combine with AND. No sort uses numeric key order as a stable baseline; the UI's default is `updatedAt:desc`, and `sort=none` explicitly records the third header-click state. Queries matching more than 5000 tasks return validation rather than silently truncating results. All filters and ordering execute in SQLite on a single read snapshot.
29. **Versioned task edits.** Desktop edits and the existing MCP update DTO call one core patch service. Omitted nullable fields stay unchanged; explicit null clears them. The version comparison and patch run in the same immediate transaction. `updated_at` advances by at least one nanosecond even for successive operations in one clock tick. Task details add `history` (last 50 events) while retaining `activity` (last 20) for existing consumers. Specta field overrides describe the nullable wire values without replacing their custom deserializer.
30. **Mock reload checkpoints.** The mock remains an in-memory service. Only the browser mock singleton optionally checkpoints its state to sessionStorage so URL reload acceptance can preserve the jam; independent unit-test instances do not persist. Storage failures are caught. Board-wide query invalidation runs once per event batch, while task-specific invalidation and actor notifications retain each event.
31. **Local runtime information and capture isolation.** `runtime_info` exposes the actual database directory and sidecar path for agent config copying and reproducible local captures. `seed_bulk` is registered only in debug desktop builds; mock seeding is allowed only in mock/dev builds. `--fresh` refuses to reuse an existing jam and requires a running app in `.dev-data/capture-*`; it never deletes or relocates a running database. Capture scripts use the runtime's actual database path.
32. **Flat table URLs.** The router parses search parameters as strings before per-field Zod validation. This preserves text searches such as `q=12` and the literal `archived=1` instead of coercing them to JSON numbers. Invalid values are ignored independently. Table results and tag suggestions use `['tableTasks', query]` and `['tags']`; both are invalidated by board events. Task and runtime data are loaded before opening the palette, whose search is local.

33. **Time ordering and agent configuration.** SQLite ordering pads the UTC RFC 3339 fraction to nine digits in its comparison expression, preserving nanosecond order without changing stored timestamps or rounding to milliseconds. Palette configuration includes the actual `JAM_BOARD_DATA_DIR`, as in the existing MCP documentation, so a development or capture window and its agent open the same database.

34. **Fixed row rendering.** Table rows keep task keys as React identities for focus preservation. Fixed 44 px rows use CSS containment and `content-visibility` for overscan, with normal React batching (`useFlushSync: false`) in TanStack Virtual. The shared expiry clock preserves unchanged highlight/pulse/toast references. These optimizations do not relax the 16.7 ms acceptance threshold; the measured failure remains documented in the M4 report.

35. **M4.1 performance method (supersedes the M4 measurement).** The `perf` Playwright project builds the mock app in production mode and serves it with Vite preview on loopback port 1422; functional tests keep the development server on 1420. Each scenario starts with exactly 2000 tagged tasks with human/agent assignees, calibrates the display from the median of 30 idle rAF intervals, warms up for one second and measures for three seconds. Inputs and thresholds are exactly those in the M4.1 request. Metrics run without tracing; a separate equivalent pass records raw CDP timelines. The former development/full-range result remains under `legacyM4` in `table-performance.json`; `before` and `after` use the new method. Raw synchronous Layout events are attributed to application callbacks, the prescribed test driver, or browser frame processing; their total is never reported as zero when it is not zero.
36. **M4.1 fixed virtual window (supersedes decision 34's rendering details).** Rows stay keyed by task key and use a memo comparator for key/version/highlight/selection plus independently changing display props (member, tab stop, cached time text). The table reads stores once, delegates row input events, caches English time labels on one shared 30-second clock and uses native title tooltips and plain CSS avatars/stamps. A small adapter over the same TanStack Virtualizer lifecycle commits only when a five-row block, count or viewport changes; its lifecycle and listener cleanup are tested. It retains at least ten overscan rows. One explicitly sized, contained tbody moves with translateY while 44 px rows remain in normal flow; this avoids individual absolute positioning and isolates layout from the rest of the page. Synchronous block commits avoid the delayed wheel updates observed with asynchronous batching. The static filters/header are outside the scrolling component. Hover background transitions are immediate, preventing 600 ms transitions on successive rows. Paper grain remains visible on a compositor layer. These changes add no package or domain rule.
37. **Status paper and unclipped decoration.** The card's inner paper uses the requested clipped outline and folded 14 px corner. Its uncut motion wrapper preserves the critical tape, drop shadow and outer agent highlight; the inset agent edge belongs to the clipped paper. Light/dark mixes are 22%/30%, with 14%/24% hover mixes and the specified 55% border mix. The inner element keeps the `task-card` CSS class; the wrapper keeps the test/key/layout identity. Column underlines, tokens and table status stamps are unchanged. Contrast is calculated from actual token and CSS mix values for normal and hover states.
38. **Drawer controls and English Due display.** The existing Drawer accepts leading/action content so key, Copy, menu and Close share a single 56 px sticky row. Save contains an intrinsic-width Kbd rather than the one-letter shortcut style. Due uses an English display button and mounts native datetime-local editing only after activation; its native picker remains available. An explicit h23 hour cycle matches the brief's `Oct 21, 18:00` example while retaining the local timezone and UTC wire value. Empty and filled displays, clearing and both drawer widths are tested.

39. **M5 archive migration and active jam.** Migration v2 adds a checked `jams.archived` flag. The latest created jam remains the selection boundary: archiving it returns onboarding instead of silently reactivating an older jam. One `jam.archived` event covers the archive operation; tasks, links, comments, members, assets and history remain physically present.
40. **M5 event names and member compatibility.** Asset edits and member edits use `asset.updated` and `member.updated`; unlink uses `asset.unlinked`. Each domain action has one activity record. Desktop MemberWithStats includes five counts and structured workingOn task references; the accepted MCP MemberStats shape is preserved. Settings and presence remain metadata without board activity (decision 2).
41. **JSON snapshots.** Version 1 exports the active jam including archived tasks, its tags/assets/links/comments/history and the shared member registry, excluding settings, tokens and the recent-call log. Import validates references, unique ULIDs, enums, tags and timestamps, caps input at 32 MiB/5000 tasks, maps existing handles without overwriting their identity, allocates fresh IDs/keys and restores history in one transaction plus one new jam.imported event. Idempotency keys are cleared on copied tasks because their uniqueness is global per creator.
42. **Exact-file image previews.** Only asset_preview(id) resolves a registered image path, canonicalizes it, checks existence and allows that exact file in the initially empty Tauri asset-protocol scope. The command returns the local asset URL; remote/missing/non-image files return null. No frontend filesystem plugin permission or directory wildcard is granted. The new protocol feature brings http-range (MIT) transitively.
43. **Live MCP runtime and stdio call metadata.** A managed runtime starts/stops HTTP and cancels active RMCP sessions; regeneration replaces the local token and restarts HTTP when enabled. A separate authenticated TCP listener binds only 127.0.0.1 on an ephemeral port, even when HTTP is disabled. The port alone is settings metadata. The stdio process sends bounded call metadata with the existing local token; only a 20-entry in-memory ring receives it. No arguments or call log are stored in SQLite. An unavailable window never breaks a tool result. A typed mcp-calls-changed event refreshes settings/presence.
44. **Secrets and configuration.** Rendered snippets are constructed from public status fields and a masked token. Full tokens/snippets are fetched only after Show/Copy; Show expires after 30 seconds and is cleared on section changes. Codex uses TOML basic strings escaped through JSON string encoding and bearer_token_env_var; its copied HTTP comment gives the token to place in that environment variable. Claude terminal examples use PowerShell single-quoted literal Windows paths (apostrophes doubled), preserving backslashes and spaces. Both stdio snippets include the actual data directory.
45. **M5 presentation and activity reading position.** Assets use the prescribed 240×168 paper cards with newest first. Source locations stay read-only in Edit because update_asset accepts only name, notes and kind; File/URL source selection belongs to Add. Activity pages backwards by sequence in batches of 30, deduplicates, uses the table's shared 30-second clock, and holds new events behind a count button while reading older entries. Native file drop creates references without copying files. Sound is persisted in SQLite and throttled to one rustle per 400 ms; the UI store only mirrors it. The fifth approved chibi, danil-wave, is copied from out and converted locally. The existing Tauri-generated icon remains readable at 16/32/256 px.

Registered image previews use contain and natural-size pixelation below 129 px; other assets keep the same stage. Team grids stretch cards and pin workload to the bottom.

Assets, Team, Activity, Settings, the table, drawer, palette and Markdown are lazy; motion and roughjs are vendor groups. A local logs/app-ready.json receipt contains only process ID and Unix milliseconds.
