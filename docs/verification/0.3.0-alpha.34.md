# 0.3.0-alpha.34 — saved-answer continuation and combined polish checkpoint

## Supported behavior, not automatic wake

Confirmed human answers and persisted **Inbox → Answered** cards offer **Continue
in brain chat**. It reveals a selectable prompt with exact project/question/scope
IDs; the answer and conversation contents are not copied into it. The board is
the source of truth. The prompt requests fresh context, current appointment and
authorized-phase checks. It asks for the language of original human notes/latest
request, asking when unclear rather than translating existing human content.

Copy is explicit. Pending/failed answers do not produce a new saved receipt.
Clipboard failure retains selectable text, repeat pending copy is single-flight,
and project ABA/unmount suppresses late feedback. A dispatched clipboard write
cannot be undone. The preview uses scoped spacing, wrapping and theme tokens.

An agent actively waiting through existing MCP tools can read the answer. A
finished conversation is **not automatically awakened**. No session adapter,
external message, CLI/API process, credentials, automatic appointment, Start,
claim or worker launch is added. An answer supplies information, not permission.
The separate embedded-agent HTML concept is not part of this production code.

## Behavioral evidence

The answer lane passed 28 focused DOM checks, including 11 new cases for pending,
failed and confirmed answers, persisted Answered access, scope/ABA/unmount,
clipboard failure and duplicate suppression. Independent review accepted the
captured receipt and clipboard boundaries. Prompt assertions verify instruction
text, not model compliance or a real agent being awakened.

One additional hosted-browser scenario saves a fictional Russian answer, reloads
the Answered view, compares the exact clipboard prompt and persisted task state,
and asserts no unrelated write/claim/execution action. It also checks the revealed
preview's bounds and readable computed text at 800×600 in light and dark and saves
screenshots for inspection. Typechecking/discovery is not an executed browser pass.

## Remaining acceptance / publication boundaries

New and repaired hidden surfaces require exact-package native inspection; the
existing tool-side AT-SPI text-entry limitation is not bypassed. Native English or
Russian writes/comments/autosave not actually exercised remain NOT RUN. Hosted
functional-browser execution is a separate gate after an authorized own-branch
push. Source/build/hash results establish integrity, not usability.

Image-resolution selection does not prove all reference text is sharp under
fractional zoom, nor establish 500-card gesture performance. Frame/control geometry,
empty-column typography, nested select clipping, bell pagination, Refine modes,
presence wording and pending/recovery overlays are included in the combined
acceptance plan. No Windows installer/GUI, installed upgrade, complete accessibility
certification or real paid-model workflow pass is implied.
