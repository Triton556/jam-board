## Upgrade boundary

On first open, existing boards are backed up and upgraded to database schema
v10; alpha.47 refuses v10 boards, so returning to alpha.47 requires restoring
a pre-upgrade backup instead of opening the upgraded database.

Source: `crates/jam-core/src/db.rs:92` reads the schema, `:96`–`:106` backs up
existing versions 1–9 before `:129`–`:132` migrates to v10. Folder-board backups
use `.state/backups/schema-v<old>-<id>/board.db`; legacy databases get a sibling
`pre-v10-<id>.backup.db`. The alpha.47 source refuses `version > 9` with
`Newer schema: writable open refused`. This is source inspection, not an
executed native upgrade/restore check. Snapshot format is v4.
