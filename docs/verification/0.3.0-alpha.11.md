## Correctness and interaction regressions

- Paginated reads preserve all output fields, sort/offset boundaries, empty-status
  behavior, exact/case-sensitive member handles, Rust Unicode matching, archived
  records, questions and foreign-ancestor refusal. Candidate filtering and hydration
  share the same transaction snapshot; separate offset pages do not promise a
  frozen board across unrelated concurrent writes.
- Table Ready true/false results match task/MCP readiness for every Rust whitespace
  scalar, empty fields and padded meaningful Unicode. A unit guard compares the
  complete whitespace set. A separate real-Store regression covers 28 accepted
  NUL cases across all seven required text fields. No stricter text validation or
  changed readiness/execution policy is inferred from these parity fixes.
- Happy DOM uses explicit synthetic viewport dimensions to check the actual table
  virtualizer's bounded 2,000-row window, filter counts, numeric ordering, row
  activation, delayed old-project results and preserved draft cache. It also checks
  fifty unscoped actors remain quiet, fifty scoped actors activate only their own
  tasks, and the explicitly extreme 2,000-actor stress fixture remains truthful.
- Open planning handoffs retain their inspected project ID/scope across selection
  and rename; a missing app project disables handoff, while the generic prompt asks
  for identity confirmation before board reads. Copy failure/reopening retains usable
  text without an old receipt. MCP prompts read live schemas, use optional guidance,
  refine existing epics first and do not invent Brain appointment or work permission.
- Report shortcuts request explicit instant scrolling and retain focus/comments/test
  choices. Report disclosures reuse monochrome CSS ink while native details/summary
  semantics remain intact. DOM/source checks do not establish new native geometry.
