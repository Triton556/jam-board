# 0.3.0-alpha.29 — human descriptions before agent structure

## Scope and behavior

This increment responds to the manual-test finding that a person could not easily
find where to describe a Story or Task in their own words. It is based on the
published alpha28 tree, not on the user's active Windows data or the separately
paused installer work.

- Task **Description** uses the existing `descriptionMd`; real **Comments** now
  follow it. Story **Description** uses its existing `outcomeMd`.
- **Agent plan** starts closed around the existing structured fields and Story
  acceptance list. Closing it keeps fields mounted and registered; their drafts
  and readiness/review meaning do not change. Its explanation and save errors are
  outside hidden technical fields. The archived Task disclosure remains readable
  while its editing controls stay disabled.
- A task without a saved description may show its existing goal as **From the
  agent plan**, explicitly not copied into the description. No model generation,
  translation, automatic summary, description migration or semantic rewrite occurs.
- Task comment drafts use the existing in-session, entity-scoped draft cache.
  Posting captures the body/target, locks duplicate pending sends, keeps uncertain
  errors with the draft, and fences completion against project changes, including
  A→B→A and unmount. It is not server idempotency or cancellation of a dispatched
  request. An error can follow persistence; inspect fresh data before an intentional
  retry. Draft retention is not durable across an app restart.
- Active-work description edits and comments still use existing revision rules.
  They do not change the holder, lifecycle generation, execution grant or report.
  A worker's old task version may become stale and must be reread/reconciled rather
  than silently refreshed and replayed.

Story-level comments are not present in the model and are not simulated with
**Open decisions**. Refine still prepares a prompt, not a launched or automatically
regenerated agent session. The requested References frame/inline-note, notification
history, shorter prompt and zoom work remain active next increments, not alpha29
features; raw session streaming remains a future investigation.

## Behavioral evidence

Two initial red DOM probes reproduced the missing primary Description surfaces on
alpha28. During this increment an extra archived-state probe found the new
Task disclosure inside a disabled fieldset; the fix leaves only technical editors
inside the disabled fieldset. The failing evidence was retained before repair.

The full React/Happy DOM suite passes **528 tests in 72 files**, including **19 new
human-first behavior probes**. These assert actual input and saved field values,
not snapshots alone:

- Description and comments precede the closed plan; existing descriptions, complete
  brief fields and legacy empty descriptions are preserved without opening writes.
- Description-only saves use the captured task revision and do not rewrite its
  brief, scope or status. Failure keeps the draft; concurrent agent changes produce
  conflict rather than an overwrite.
- Story Description saves exactly `outcomeMd`; other intent/acceptance fields stay
  unchanged. Switching Stories preserves the correct in-session draft.
- Structured input remains the same mounted node with the same draft across
  collapse/reopen. Archived fields stay disabled while the disclosure can open.
- Repeated pending comment actions send once. Unconfirmed errors retain the draft;
  project change/ABA/unmount suppress stale completion. Cyrillic comment content
  is preserved while a separate unsaved Description remains unsaved and intact.
- Description and comment changes on an assigned In progress task preserve holder,
  status, generation, review round and evidence. The old task version is refused.

Existing draft, read-failure and tab tests use the new labels and explicitly open
**Agent plan** before inspecting technical fields. Their interruption, conflict and
persisted-state assertions remain; no test was skipped or timeout increased.

Two new functional-browser scenarios cover real input/disclosure actions, persisted
mock-bridge fields, comments, retained technical drafts, keyboard summary activation
and computed list-row spacing. They are typechecked and discovered, **NOT RUN at
this source checkpoint**. Existing browser callers now open the named disclosure
rather than treating hidden controls as directly visible.

## Interaction map and acceptance limits

[docs/agents](../agents/README.md) now contains the user interaction tree, all
baseline MCP actions and state distinctions, stable acceptance IDs, UX rationale,
remaining gaps and a per-feature maintenance checklist. Repository `AGENTS.md`
points contributors to this map. HF01–HF05 have the named DOM behavioral evidence
above, not a blanket visual pass.

The spacing/style assertions and mounted-input behavior are not native pixel
proof. Both-theme open-state layout, long descriptions/comment threads, Windows
focus/pickers and a fresh human discoverability trial still need their respective
acceptance routes. Preserve the inline reports/results already valued in the
manual test. No broad accessibility certification, automatic agent launch,
translation, Story comment system or session-streaming capability is claimed.
