# 0.3.0-alpha.22 verification — 2026-10-21

## Reproduced scope

Independent alpha20 tests suppressed native notifications and delayed persistence
until after returning to the originating Assets view: same-project navigation and
A → B → A, each with success or a post-persistence rejection. The old continuation
correctly stopped but the new page could remain stale. An explicit **Refresh
assets** now reads that project without replaying the write. References has the
same read recovery, and problematic receipts tell the user when to refresh.

Independent alpha21 probes also showed cached list failures unmounting References
note, Board quick-capture and Plan new-epic drafts. The fix keeps those editable
subtrees mounted with a last-loaded-view warning. No-data errors remain blocking
and retryable. The already-safe Table inline draft is a negative control, unchanged.

Pre-fix evidence is retained in `.dev-data/audit/alpha20-independent/`,
`.dev-data/audit/route-draft-alpha21/` and
`/tmp/alpha21-read-recovery-expected-red.log`. Native-bridge tests use actual App,
router and generated command bindings with only transport/events modeled; they do
**not** prove native filesystem/DB writes. Route draft tests use production page
components and QueryClient with mock API/router hooks, not a real router or GUI.

## Limits and remaining closure

No new native GUI, current external CI, Windows installer, publication or visual
geometry acceptance is claimed. Alpha19 native acceptance is separate. File-batch
receipts remain bounded in-memory notices, not guaranteed delivery or a durable
queue. A refresh is a read, not cancellation, rollback or mutation retry.

The separately reproduced selected-Epic/Story Markdown draft loss on cached detail
read failures is queued for alpha23. TaskDrawer is the tested safe negative control
for that extension. Neither is silently credited to this list-recovery release.
