## Clipboard regression coverage

Single-flight is the explicit policy: while token lookup or clipboard writing is
pending, transport/copy controls are disabled and the handler synchronously refuses
an overlapping action. Once it settles, a new copy is allowed and wins normally.
Tests cover both HTTP-first and stdio-first pending orders, repeated handler calls,
visible pending state, retained clipboard after failure, explicit retry, project
switch, rapid A→B→A, and unmount. Synthetic tokens only are used in fixtures.

Project changes invalidate the delayed operation before clipboard invocation and
success receipt. A same-project rename retains the originally inspected target
label. The platform cannot retract an already-invoked clipboard write; no guarantee
of undoing an accepted write is made. Alpha9's documented copy-on-project-switch
behavior is intentionally superseded by cancellation in this version.

## Keyboard and report readability coverage

Six focused tests cover named tablists and all tab/panel relationships, one roving
entry point, wrapped arrows/Home/End, manual Enter/Space activation, unchanged
vertical scrolling, selected-tab re-entry, unsaved Notes and asset field retention,
and no automatic file picker while exploring labels. The first two probes fail on
the exact alpha9 baseline before this implementation.

The report test checks focus shortcuts, preserved comments/test selections and the
absence of a nested vertical height/overflow rule. All captured evidence and frozen
review validators remain unchanged. This is DOM/source evidence; the actual new
single-scroll geometry still requires the next native acceptance pass.
