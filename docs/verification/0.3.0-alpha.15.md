## Capability and policy

`get_session_context.latestActivityCursor` is `max(activity.seq)` restricted to the
pinned project's ID, or zero with no events. The exact identity and high-water use
one read transaction. Existing global cursors, pagination, tools, readiness,
permissions, grants, validators and schema 7 remain unchanged.

Fresh bootstrap captures the high-water **before** baseline reads, then replays
newer events. It is neither a multi-call atomic snapshot nor historical audit.
Existing unprocessed checkpoints take precedence. Bounded inclusive recovery handles
each page before storing `nextCursor`, including timeouts; a short page alone is
not completion. Saved project/scope/filter identity matters. Excluded global events
can advance a valid scan cursor beyond project high-water; that is not rewind.
There is no database-generation identity or automatic restore recovery.

All three role prompts and both board/epic resources carry the same policy. Live
waiting applies only to an assigned observation role/request and stops when that
assignment ends. Decision evidence and captured mutation/review validators remain
mandatory; no model session, monitoring assignment or execution grant is created.

The property is always present and nonnegative in this server's generated output
schema. Existing tolerant readers can ignore it; deny-unknown-fields consumers,
exact fixtures and cached schemas require an update. Missing on an older server is
not a returned zero. Tests cover both consumer shapes rather than claiming universal
external-client compatibility.

## Honest cost and runtime limits

The final shared policy is **1,955 UTF-8 bytes / 220 whitespace-separated words**.
Full plan/work/review prompts measured by the author on actual stdio were
3,806 / 3,400 / 3,085 bytes, compared with alpha12's 2,350 / 1,722 / 1,423.
These are instruction increases, not token counts or total savings. The concrete
motivation was an unbounded recovery payload on a fictional large fixture; pagination
alone does not reduce total history cost, and one event can still be large.

implementation, new latency/throughput benchmark, current GUI/Windows or external CI
acceptance is claimed. Prompt-contract tests show delivered instructions, not model
compliance. Existing registration/heartbeat behavior is unchanged; the new context
query itself adds no persistent writes. Prior volume evidence and native screenshots
