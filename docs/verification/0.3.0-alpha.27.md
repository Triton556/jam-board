# 0.3.0-alpha.27 — pointer-only Board dragging and current browser contracts

## Scope

The requested interaction change removes **Board task keyboard dragging**, not
keyboard access to the application. Space and Enter open a focused task button.
The existing Status control and Save support keyboard status edits, subject to the
same readiness, execution and freshness rules. They do not offer within-column
ordering. Pointer dragging and MCP task movement remain; Table navigation, Board
horizontal scrolling, manual tabs and brief-list reordering are unchanged.

Only the PointerSensor remains on Board. Its drag-start task revision and neighbor
calculation are retained. Board cards no longer inherit sortable keyboard ARIA or
hidden Space-to-drag guidance. Pointer announcements and Escape cancellation are
not an alternative authorization path.

The original Chromium case intermittently stopped before its destination was
reached. Its trace showed pickup followed by a drop in the original Ready column;
this did not establish a mutation/permission failure. Keyboard dragging was removed
by product decision, not declared fixed by weakening that test. The replacement
case checks normal Space/Enter activation, no keyboard-drag mutation, the existing
keyboard Status/Save route and reduced-motion agent feedback. Pointer-based probes
retain stale-start rejection, captured revision, destination neighbors, pending
feedback and read-only recovery after an uncertain result.

## Browser-contract migration

The preceding exact alpha26 CI run [39708432470](https://github.com/Triton556/jam-board/actions/runs/39708432470)
passed Windows checks and its debug desktop build, including the repaired temporary
fixture guard. Linux passed the earlier gates but reported **48/60** functional
browser cases passing. This is historical evidence, not alpha27 acceptance.

The current tests assert the intended contracts instead of obsolete wording:

- Five contextual empty-column policies, no cards, and the correct project link.
- Individual polite status summaries inside the named Notifications region;
  highlight lifetime, View action and reduced-motion feedback remain checked.
- A clipboard configuration containing the actual token and captured project ID,
  with a project-specific receipt; masking and token rotation remain checked.
- The reviewed 14% light / 16% dark card-color mixes, still measured via computed CSS.
- Markdown prose in its own reading surface, separate from Edit controls. Queued
  saves, exact persisted content, entity targeting and newer unsaved drafts remain.
- Visible Epic/Story/task hierarchy counts and scoped planning handoff. Epic
  Stories/Journal remain segmented **radio** controls; Settings' connection tabs
  remain manually activated tabs.

The ordinary application TypeScript config did not include E2E sources. The new
`npm run typecheck:e2e` uses the same strict options over all browser scenarios,
including performance fixtures, and runs in both CI jobs. It exposed five existing
type errors in `polish.spec.ts` and `v25.spec.ts`: missing layout elements now fail
explicitly, and optional-valued API fields are supplied as `null`. Existing visual
and journal assertions are unchanged; dependencies and compiler strictness are not
relaxed. The performance scenarios are typechecked, not claimed executed.

No functional scenario is skipped, no mutation is retried to force a pass, and no
browser timeout is increased. The remaining **60** listed scenarios still require
the actual Chromium CI run; listing them is not executing them.

## Limits

Pointer unit tests use real dnd-kit sensors with explicit synthetic column/card and
overlay rectangles in Happy DOM. They establish event/CAS behavior, not native
geometry. No denied local headless/AX route was retried. This change does not add a
Move menu, an OS-agent launcher, a schema migration, new permissions, authentication,
transactional rollback or general mutation idempotency.
