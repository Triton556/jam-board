## Eight focused onboarding probes

- Named project, per-Epic appointment and optional installation are distinct;
  rendering setup does not reveal credentials, install files or grant execution.
- Read-only prompts capture the exact intended ID/prefix and stop before other
  board reads when the connection is wrong. Copy receipts name that target.
- Stdio copy uses captured settings and does not fetch an unused HTTP token.
- A pending HTTP token read plus changed UI selection still copies the original
  inspected project ID; the receipt does not claim the later selection.
- Mismatched settings disable configuration/check actions, with explicit reread
  recovery instead of an unbound copy. The setup CTA focuses its configuration.
- Source instructions open only on the user's click; failure reports a manual
  recovery route without claiming a download or installation.
- The clone command is copy-only and remains selectable after clipboard failure.
- Planning handoffs defer to live schemas, prohibit blind stale replay and keep
  per-Epic appointment separate from model launch or execution authorization.

These are DOM/mock-bridge tests, not proof of an external model following prompts.
Native initialization also asserts general-project wording through real stdio.
