## Cause and bounded correction

A realistic userEvent regression reproduced the same failure: complete a guarded
save, then present a new geometry/selection projection of the unchanged old query
row before its refresh arrives. The hook compared that cloned object with its new
acknowledged baseline and mistook the old observation for an external edit.

The editor now remembers the last incoming observation separately from its own
save acknowledgement. Identical ID, heading, body and update marker are ignored
on re-presentation. This uses equality, **not chronological timestamp ordering**.
A different body with the same marker, or an actual return to old text with a new
marker, still stops autosave and retains the draft. Exact-content/same-marker ABA
is not revision history; the existing server expected-content comparison still
protects subsequent writes. No server guard, project fence, uncertain-create
no-retry rule, schema, MCP tool or execution authority was removed or weakened.
