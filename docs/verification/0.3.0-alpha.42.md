## Changed behavior

- Project-pinned Brain dock supports ACP chat, terminal sessions and built-in
  API chat, connection/auth recovery, attachments and staged board context.
  Refine/Continue/Ask brain stages editable drafts; it does not Send or grant Start.
- Local voice input uses an on-demand whisper.cpp sidecar, resumable verified
  downloads, CPU/CUDA selection, warm-up and idle unloading.
- Canvas frame/entity links, Keep / Not this feedback, note-to-task creation,
  grouped gestures and 52 MCP tools preserve project isolation and human intent.
- Interaction-walk fixes cover focus, keyboard menus, pending/retry feedback,
  retained drafts, hit targets, lazy recovery, text sizing and themed scrollbars.

### Hosted round 1 and ZIP extraction correction

- Candidate `5d7d743565e70656cea43e454d477ab1357dc211`:
  [main CI 40261643753](https://github.com/Triton556/jam-board/actions/runs/40261643753)
  passed Clippy on both OSes. Ubuntu then failed four `jam-voice` tests in
  `cargo test --workspace`: auto-install, digest retry, cancel/resume install,
  and ignored-range recovery. Three errors were `Cannot inspect whisper.cpp
  archive`; the cancellation test failed before reaching its expected download
  cancellation. No release tag was changed on this candidate.
- Cause: fixtures and upstream Windows runtimes are ZIP archives. Windows uses
  libarchive `System32/tar.exe`; Linux selected GNU `tar`, which cannot list or
  extract ZIPs. Linux now explicitly selects `bsdtar`, and Ubuntu CI installs
  `libarchive-tools`. Existing archive path/link rejection and digest validation
  remain in place. A missing archive tool reports the Linux dependency clearly.
  Other Unix systems retain their existing `tar` command. The four existing
  download lifecycle tests exercise actual ZIP inspection/extraction on CI;
  they are not disabled or replaced with platform skips.
- Round 1 main Windows job completed successfully. A local same-ZIP probe with
  Git for Windows GNU tar 1.35 failed with exit 2 (`This does not look like a tar
  archive`); Windows System32 libarchive tar listed it with exit 0.
- Fresh Windows formatting, all-targets Clippy, version consistency and diff
  checks passed after the extraction fix. The first workspace test rerun hit an
  intermittent 10-second `pty_batch_launch_preserves_inline_json_and_argv`
  timeout. With no source change, its exact targeted rerun passed in 0.36s and
  the subsequent full workspace run passed. This timeout remains an observed
  intermittent limitation; it was not hidden by skipping the test or raising
  its deadline. Hosted round 2 is pending at commit time.
