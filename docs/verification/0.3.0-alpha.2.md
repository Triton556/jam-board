# 0.3.0-alpha.2 verification — 2026-10-21

Development candidate, not a published release. Checks use fictional data in a
cloud Linux workspace; no existing user board or installed application is changed.

## Passed

- Version consistency across Cargo/npm/Tauri manifests and lock metadata, plus
  three Node regression tests for that check.
- Frontend Biome check, TypeScript check and production Vite build.
- 184 frontend tests in 22 files (Happy DOM / isolated mock bridge).
- 109 Rust workspace tests: 81 core, 9 MCP (including real loopback HTTP),
  10 real stdio and 9 native (library plus integration).
- Workspace all-targets Clippy with `-D warnings`, native compilation/linking and
  generated TypeScript bindings.
- `git diff --check`; Playwright discovers 68 specifications in 17 files.
  Discovery is **not execution**.

## Covered behavior

- Ready alone cannot authorize work. Every work-entry path requires an effective
  story/epic grant; existing holders can still report after pause or archive.
- Epic inheritance, separately paused/started stories, parent and sibling changes,
  stale approvals, imported closed scopes, reopening, additive v6 migration and
  restart persistence. Import and migration never grant new execution permission.
- Human-only native decisions; appointed-brain typed requests; unknown approval
  flags rejected; generic questions cannot grant work. Real MCP sessions preserve
  identity/project boundaries, including across UI selection changes.
- Independent store pools exercise claim/pause serialization. Pending requests
  and decisions are revision-bound and project-pinned.
- Archived In progress tasks remain in safety counts and prevent project archive.
  Unarchiving preserves holder/status/round and does not resume the scope.
- Shared assignee membership survives project export/import. Picker summaries
  refresh after mutations/revisit, and canceled old-project results cannot replace
  the newly selected board.
- Exact-scope confirmation, cancel/error/retry, stale-project rejection, persistent
  Inbox/review receipts, stable keyboard focus and duplicate-submit prevention.

## Evidence boundaries and open checks

- Independent alpha1 review reproduced two defects (shared-assignee export and
  stale project summaries). Both have regression fixes here; independent retest
  of this exact candidate is pending at commit time.
- Interactive browser Playwright execution is not verified: the local browser
  transport could not reach the dev server; the owner-private mock preview requires
  sign-in unavailable to that browser. No authentication/privacy setting was relaxed.
- A separate native QA worktree successfully launched alpha1's Linux AppImage and
  exercised fictional data in the real GUI. That is not a visual approval of this
  changed alpha2 UI. Exact alpha2 rebuild, screenshots and interaction checks are
  the next acceptance step.
- No Windows packaged upgrade/uninstall or real external brain/worker session was
  run. Rust/stdio integration and mock UI tests do not substitute for those checks.
- Known UI follow-ups: compact Plan rail hides its filter/title below 1360px,
  Enter on a board-card drag activator needs distinct open semantics, and filtered
  Doing counts should not hide project-wide overload. These are tracked usability
  defects, not execution-authorization bypasses, and are the next iteration.

Reproduce with Node 24 and stable Rust. Native Linux checks require GTK3 and
WebKitGTK4.1 development libraries; this workspace uses a user-local official
Debian sysroot, not a system package or security-setting change.
