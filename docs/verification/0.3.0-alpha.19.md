# 0.3.0-alpha.19 verification — 2026-10-21

This bounded batch addresses table entry and narrow Story permission readability.
No backend, schema, mutation, execution grant, import or dependency behavior changes.

## Evidence and limits

The restricted alpha16 native read-only pass observed a focused table-row sliver
under the sticky header: Enter opened a different task from the first readable row.
It separately observed vertical viewport reset while tabbing to sort headers and
cramped Story permission counts/actions. Saved evidence remains under the native
QA fixture's `acceptance-alpha16.md`; those observations are not alpha19 acceptance.
Horizontal scrolling to expose a far-right focused sort control is not itself
classified as a defect.

The table's desired-behavior pre-fix run had **8 failures / 14 passes** at
`/tmp/alpha18-table-readable-expected-red.log`. It includes sub-row offsets 1, 22,
43 and large equivalents, a partly visible remembered bottom row, the last row,
and viewports with only 22px available. The fix prefers whole visible rows and
uses the center-overlap row only when none fits. Existing keyboard sorting,
filter focus, row identity, empty recovery and virtualization checks remain.
The new tests use the real virtualizer with **synthetic geometry**, not native
rendered measurements. No FPS, screen-reader or universal zoom guarantee is made.

Two pre-fix CSS/cascade tests failed in
`/tmp/alpha18-navigation-layout-expected-red.log`. Story's full-width summary and
separate action row are checked against the real drawer and stylesheet, retaining
Start text/counts. Happy DOM does not measure the resulting widths.

The [CSS scroll specification](https://www.w3.org/TR/css-scroll-snap-1/#scroll-padding)
distinguishes container-wide viewing insets from
[per-element margins](https://www.w3.org/TR/css-scroll-snap-1/#scroll-margin).
The 84px allowance now belongs to body rows, not the container containing the
sticky controls themselves. This motivates the header-scroll correction but does
**not** establish that the native header-focus jump is fixed. Actual native
comparison remains pending, as does the new Story layout's visual acceptance.
