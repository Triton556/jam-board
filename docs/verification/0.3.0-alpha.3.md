Development candidate on the local feature branch, not a published release.
All test/preview/native data is fictional; no user's board or installed app changed.

## Actual native evidence and limits

A separate detached alpha1 worktree produced a Linux AppImage and ran its real
GUI on the cloud desktop with a user-local runtime library prefix and the normal
sandbox enabled. Its packaged MCP sidecar answered real read-only stdio calls.
Onboarding/demo, native project switching, theme changes and saved planning edits
were exercised with fictional data.

That native run reproduced the hidden epic filter/title at 1180px, Enter starting
a drag instead of opening a card, and a cold first launch remaining invisible
until a second launch. This candidate fixes those causes; exact alpha3 native
rebuild, cold-launch and visual acceptance are pending. Earlier screenshot files
are baseline evidence, not alpha3 screenshot approval.

One initial focus report used accessibility-API activation, which does not imply
pointer focus. Rechecking with an ordinary pointer showed baseline card focus
restoration worked; it is not claimed as a native pointer defect. This version
adds explicit activation focus as defensive behavior and DOM-tests it.

Owner-private hosted preview access still requires sign-in unavailable to the test
browser. No privacy/authentication setting was weakened. No Windows installed
upgrade/uninstall, real external worker process, or full human/brain/worker session
was executed. The core release API works for archived recovery; a human-facing
Release claim control is the next UI slice, not yet present here.
