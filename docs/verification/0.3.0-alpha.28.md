# 0.3.0-alpha.28 — reliable Board return focus and option feedback

## Evidence and bounded repair

The [alpha27 CI run](https://github.com/Triton556/jam-board/actions/runs/39712846366)
reported **58/60** Linux functional scenarios passing. Its two failure snapshots
showed a correctly rendered Settings-local configuration receipt (the test looked
inside Notifications), and Epic Overview selected after URL navigation without a
Stories tab (the test searched for a Stories-only task row). The corrected tests
use the exact local status and explicitly select Stories. Clipboard token/project
contents, masking/rotation, report decisions, question answers and persisted state
assertions are preserved. No timeout increased and no scenario was skipped.

The exact alpha27 native Linux pass was **partial**, not full acceptance. Normal
Space/Enter activation, keyboard Status/Save and a separate pointer move passed,
with exactly two intended task changes and two activity events. After the Status
save moved a card, closing its drawer lost focus; the active Status option also
lacked its intended highlight. The latter was traced to a more-specific transparent
CSS rule overriding the active-option background.

A real-App/router/MockBridge regression reproduced the disconnected opener and
lost focus on immutable alpha27. The repair resolves the originating task by key
when the drawer closes. It is fenced by the originating Board's mount lifetime
and project-selection generation, including A-to-B-to-A. Missing/archived/filtered
cards, or a saved status not yet reflected in the Board list, use the stable Board
entry. A later read never moves focus again. An older dialog cleanup cannot steal
focus from a newer layer; nested dialogs retain their parent-control priority.
Lazy task loading/error and the loaded editor share the same optional resolver.

The CSS repair is limited to the active option selector. Two new Chromium cases
check the resolved background in light and dark, with the pointer away from the
popup so hover cannot mask the defect. They check active-versus-selected ARIA,
movement of the highlight, and unchanged task data after Escape. These browser
checks are not claimed run by DOM tests or source inspection.

No task-mutation semantics, permissions, schema, MCP contract, dependencies or
keyboard-drag feature changed. Board keyboard dragging remains removed; ordinary
keyboard navigation, Status editing and pointer movement remain.

## Limits

The new focus probes use Happy DOM and the real React/router/query code with a
fictional mock bridge. They do not establish native pixel geometry. The active
option computed-style checks require the hosted Chromium run; native alpha28
acceptance requires its own exact package. Neither is inherited from alpha27.
No denied local headless, accessibility-tree or held review interaction was retried.
This is not a general accessibility certification, mutation idempotency guarantee,
new Move menu, or OS-agent launcher.
