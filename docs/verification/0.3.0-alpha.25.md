# 0.3.0-alpha.25 — capture-routing clarity

## Scope

This is a copy/docs/test correction, not a task-reparenting feature. The unfiltered
Board quick-capture card now says that the draft goes to Unplanned work; the
Epic-filtered card instead asks for a Story. Both disclose that an existing task's
Story cannot be changed by an exposed UI/MCP action. Refining the brief before
Ready does not change its parent or authorize execution.

The walkthrough documents two existing routes to the intended Story:

- Plan → open Story → **+ Task**, which submits that Story key;
- Board → filter by Epic → **Add task to Backlog** → **Story for new draft**.

Without an Epic filter, native quick capture reuses an existing Unplanned work
Story or creates a draft Epic and Story when needed. No mutation schema, migration,
permission, default placement, claim, or execution policy changed.

README and the walkthrough correctly place **Switch project** in the top bar.
Brain appointment includes the visible **Plan → Epic → Brain** route. Connection
identity guidance retains the distinction between separately named connections
and additional chats/subagents inheriting one member identity.

## Limits and attribution

A native mutation can persist in `execute_with_store` and then return an error
from feed polling, selected-event filtering or event emission. Consequently a
returned error does not universally prove no write. Pending duplicate-click locks
are not idempotency for a later intentional retry, and the creation UI does not
provide a universal committed/not-committed receipt. Inspect fresh project state
before retrying an uncertain creation; no automatic replay is performed. Tests
that model known pre-write rejection do not establish rollback after every native
error. This is a documented limitation, not a notification/idempotency redesign.

No new browser/native geometry claim is made for the longer quick-capture hint.
The new frontend routing checks use the mock bridge; the Store test separately
checks real persistence. This does not establish native task reparenting, which
is not implemented. Existing historical native acceptance belongs to its exact
version/package, including alpha23's positive two-file registration; it is not
relabelled as alpha25 acceptance.

The preceding alpha24 clipboard pipeline independently passed 25 checks in four
files using actual App/router/generated bindings with modeled native transport,
image preparation and persistence. That bounded review did not test a real native
clipboard race. The exact alpha24 Linux package also passed a bounded normal-launch/read-only
follow-up with all 21 business-table hashes unchanged. That run did not reproduce
a native clipboard race or view this version’s updated hint.

Earlier accessibility-runtime, Windows installation, external-CI
and publication limitations remain unchanged. No public release/tag or user
machine installation is implied by this prerelease version.
