## Scope

This candidate combines unchanged canvas30 surfaces with Project notifications,
explicit Refine context modes, honest Board presence and nested-select placement.
It does not modify the user's running Windows test, add a model integration or
change database/MCP/execution semantics. Versioned alpha29/30 source and evidence
remain distinct; no native result is transferred to changed source.

- [Notification contract](../agents/notification-history.md): existing persisted
  project activity, seven actionable agent event kinds, bounded pages, session-only
  read watermark, exact validated View. This is recent project updates, not proof
  that a toast was delivered or a human approved it. Raw event payloads only trigger
  rereads because they lack project identity. No automatic unbounded history scan.
- [Refine modes](../agents/refinement-modes.md): captured project/entity IDs, local
  session-only wishes, explicit setup versus continuation. No inferred chat memory,
  clipboard delivery/board save/agent launch. Both keep planning-only boundaries
  even for a running scope. Short human-language summary guidance is not a model
  compliance guarantee or new readiness condition.
- [Presence](../live-card-presence.md): one Root visible 30-second reader plus visible
  return; project/ABA/lifetime/query-generation fences before shared-cache writes.
  Cards distinguish current claim/status evidence from unconfirmed or historical
  activity and quiet waiting-review state. No structured reviewer signal was added.
  The heartbeat cache defect is reproduced; the user's minimize/restore incident
  is not conclusively diagnosed by that fact.
- [Overlay placement](../agents/overlay-placement.md): same modal-tree/select
  semantics, bounded above/below placement within visible clips, resize/scroll
  remeasurement. No new menu or task-movement policy. Monochrome Agent plan marker,
  archived help and singular counts are small native-observed polish repairs.
