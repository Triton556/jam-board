# 0.3.0-alpha.13 verification — 2026-10-21

Local development candidate, not an external release. This batch repairs table
keyboard/draft recovery and makes existing navigation/permission states clearer.
No backend or schema changes; the separate bootstrap-cursor proposal is not included.

## Reproduction and scope

Independent alpha11 probes established missing Tab entry after a 2,000-row virtual
scroll and focused-row deletion. Owner alpha12 probes separately established an
inline table-create completion erasing a newer draft after Escape/reopen. Original
probes/results remain under ignored `.dev-data/audit/` and `/tmp/alpha12-inline-create-audit.log`.
Three additional alpha13 red probes show why merely mounted overscan is not visible:
top and bottom overscan, plus a remembered row while search owns focus. Their
pre-fix result is `/tmp/alpha13-overscan-red.log`; all pass after the repair.

The table preserves its bounded virtual window and ten-row block batching. Between
window commits, only mounted row tab stops change; genuine row focus moves to a
visible fallback without snapping a pointer scroll backward. An input/filter keeps
its focus. Data reorder preserves task identity when possible; keyboard destinations
explicitly reveal the row past the sticky header. Read errors offer Retry without
resetting filters. Synthetic geometry is explicit, not native layout evidence.

Inline creation captures submitted values/project, synchronously refuses duplicates,
keeps a visibly pending form and fences old completions after unmount/project changes.
Its error/status editor is above the fixed-height virtual header. Known errors retain
the draft; retry is an explicit new action. This is distinct from alpha12 Plan dialogs
and the unchanged Board QuickCreate. No timer converts an uncertain write into a
known failure, and hiding/closing the application does not cancel a submitted write.

## Limits and next acceptance

No native GUI, current-browser runtime/frame-time, Windows installation or external
CI pass is claimed for this candidate. Earlier native Linux screenshots are not
relabeled as alpha13. Theme color calculations cover declared semantic use sites,
not a rendered WCAG certification. In particular, visible board controls, inline
editor geometry and real keyboard focus at zoom need later native/browser acceptance.
The existing Linux accessibility-query freeze remains an unresolved environment/
runtime observation; this source change is not claimed to repair it.

Asset/reference save recovery and project-settings draft reconciliation remain a
separate confirmed follow-on batch. An additive session-cursor patch is also separate,
so its contracts cannot be inferred from this UI version.
