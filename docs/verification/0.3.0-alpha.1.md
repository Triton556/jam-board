# 0.3.0-alpha.1 verification — 2026-10-21

Development candidate, not a published release. Tested in a cloud Linux workspace
with fictional demo data, Node 24, stable Rust and user-local native dependencies.
No existing user board, credentials or installed application was modified.

## Passed

- `node scripts/check-versions.mjs`: workspace/application/manifests/lock metadata
  match the changelog version. `node --test scripts/check-versions.test.mjs`: 3 tests.
- In `apps/desktop`: `npm run check`, `npm run typecheck`, `npm test` (153 tests)
  and `npm run build`.
- Rust core/MCP/CLI suites: 86 tests, including real stdio and loopback HTTP
  session isolation; native Rust suite: 5 tests.
- Native all-targets compilation, linking and TypeScript binding export.
- Core/MCP/CLI and native all-targets Clippy with `-D warnings`.
- `git diff --check`.

Project coverage includes legacy migration and restart, restore without changing
per-task archive flags, refusing archives with active work, immutable MCP binding,
foreign entity/resource access, interleaved stores, pending waits, project-scoped
presence and task-create retry tokens, and delayed native identity changes.
Frontend coverage includes independent project state, list keyboard selection,
planning drafts retained across switching, lost-response reconciliation, safe
planning prompts and clipboard failure recovery.

## Not verified

- Interactive browser rendering and Playwright E2E: a usable browser transport was
  not available for the local dev server. The private fictional-data preview built
  successfully but required an owner sign-in unavailable in the test browser.
  Added E2E specifications are **not a report of passing browser execution**.
- Native graphical app launch, packaged Linux installation, Windows build and
  installed upgrade/uninstall behavior. A native binary linking successfully is
  not a substitute for these checks.
- Real brain/worker execution or end-to-end human authorization. This alpha does
  not yet enforce the planned durable story/epic execution gate.
- Accessibility contrast, screenshot/layout approval and actual narrow-window
  interaction. Keyboard behavior has DOM-level coverage, not visual certification.

The screenshots already in the README document earlier application runs, not this
candidate. Mock tests cannot establish SQLite, filesystem or OS integration behavior;
those claims are limited to the separate Rust/native checks above.
