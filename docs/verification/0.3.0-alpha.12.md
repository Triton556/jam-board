# 0.3.0-alpha.12 verification — 2026-10-21

Local development candidate, not an external release. This batch repairs creation
transaction feedback in the Plan page and Story drawer, without backend changes.

## Reproduction and scope

On exact alpha11, three controlled Happy DOM probes reproduced ordinary dismissal
of a pending write followed by unexpected success navigation: Epic Cancel, Story
Cancel and Task Escape. The original probes and result are retained under ignored
`.dev-data/audit/alpha11-creation-all-audit.test.tsx` and
`/tmp/alpha11-creation-all-audit.log`. They asserted the defect before production
changes; no assertion was silently weakened to call it a pass.

The replacement shared form captures title/parent/project, refuses overlapping
submissions and visibly holds the dialog while the write is pending. Processing
text receives focus and polite status semantics; a known rejection restores the
editable draft and ordinary Cancel/Escape. An unmount or project transition,
including A→B→A before a render, suppresses stale success navigation. Same-ID rename
is not a new project. Context-read failure has an explicit retry and keeps the title.

## Limits and remaining checks

- DOM interaction is not native screen-reader or browser visual acceptance.
  Native alpha12 and current functional/performance browser execution are **NOT_RUN**.
  Earlier version-specific native evidence remains separate. No denied GUI action
  or blocked external publication was retried for this candidate.
- A pending request is not cancellable by hiding a form. Forced app shutdown or a
  lost response can leave a committed entity in the plan; inspect it before
  repeating an uncertain action. No timer invents a failure or automatic retry.
  This is neither a server idempotency mechanism nor a rollback guarantee.
- WAI's normal dialog guidance expects Escape dismissal; the temporary pending
  lock is an intentional transaction-safety exception, not a conformance claim.
  Rationale and source links are in [Workflow UX](../workflow-ux.md#15-a-pending-creation-is-not-cancelled-by-hiding-its-dialog).
- Independent alpha11 review found a separate virtual-table row-entry problem
  after scrolling/removing the focused row. It is queued for the next bounded
  keyboard/navigation batch, not claimed fixed here. Table inline creation is also
  a separate path under investigation; this version repairs the planning dialogs.
