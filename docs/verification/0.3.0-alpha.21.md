# 0.3.0-alpha.21 verification — 2026-10-21

## Scope and reproduced evidence

The reachable command-palette copy action duplicated configuration generation,
without a project binding. Its TOML apostrophe doubling was invalid for synthetic
Windows paths. The action now navigates to the existing guarded Settings → Agents
setup. Both TS and Rust Codex HTTP builders explicitly name the agent. Guidance
explains the existing global normalized-name identity contract; no identity API,
launcher, credential handling or automatic configuration installation was added.

Preserved pre-fix evidence: `/tmp/alpha20-palette-expected-red-corrected.log`
(four missing-destination checks), `/tmp/alpha20-connection-contrast-expected-red.log`
(two HTTP-header and two contrast failures), and
`/tmp/alpha20-header-expected-red.log` (Rust header failure). The first palette
harness used a wrong textbox selector; its four harness failures are **not**
credited as product evidence. The corrected harness uses the real combobox/options.

Source-based light/dark contrast checks resolve all five status backgrounds,
including the already-existing Ready → Todo → butter alias. Whole-control 55%
opacity caused inadequate normal-text contrast; removing it preserves selected
rings/pressed state and the archived stamp. This is not a native-pixel or complete
WCAG audit; paper grain and antialiasing were not measured.

## Limits and next known recovery work

Name aggregation/normalization and shared-identity consequences are source-traced
existing behavior, not evidence of the cause of any historical model failure.
The connection check does not invent a caller field in `get_session_context`.
No real client configuration, token, agent process, or independent-session setup
was modified. Native GUI, current external CI, publication and Windows installer
lifecycle were not run for this version. Earlier alpha19 native layout acceptance
remains separate, as recorded in alpha20 verification.

The alpha20 independent audit found a stopped file batch can persist late after
returning to its origin without an event, leaving that newly opened list stale;
explicit read Refresh recovery is queued. It also reproduced a References cached
read error unmounting an unsaved note dialog. Neither follow-up is claimed fixed
by this connection/readability batch.
